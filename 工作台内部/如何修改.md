# 如何修改

这份文档面向想动手改造系统的用户。按「改多深」分四层，从浅到深：

1. **改主题配色** —— 改 CSS 变量，最简单
2. **换背景图** —— 替换一张图片
3. **直接改数据** —— 手编任务文件
4. **改行为 / 布局** —— 改代码

> [!warning] 动手前先备份
> 任何修改前，建议把整个 `MyTask-OS` 文件夹复制一份留存。代码改坏了随时整库还原。

---

## 一、改主题配色（`--pos-*` token（注意：`工作台工作台内部/Styles/dashboard.css` 与 `工作台工作台内部/Views/Dashboard/view.css` 各有一份同名定义，改主题需同步两处））

整套「曜石 Obsidian」主题由一组 CSS 变量驱动，**改一处值，全站生效**。

主题 token 有两份定义，当前值完全相同：

| 文件 | 作用域 | 管什么 |
| --- | --- | --- |
| `工作台工作台内部/Styles/dashboard.css` | `.personal-dashboard`（约 754 行起） | Obsidian 页面壳（标题、行内代码、表格等通用元素） |
| `工作台工作台内部/Views/Dashboard/view.css` | `.pos-dash`（文件开头） | 工作台视图本身 |

> [!important] 两份要同步改
> 工作台视图自带一份 token（为了脱离主题也能用）。只改 dashboard.css 会发现工作台没变化——**两处同名变量一起改**，保持一致。

关键变量与当前曜石值（完整清单见上述两处定义）：

```css
--pos-bg: #0e0f11;                /* 页面底色（近黑） */
--pos-surface: #16181b;           /* 卡片表面 */
--pos-surface-soft: #1e2126;      /* 次级表面（表头、输入条等） */
--pos-primary: #e8e6e1;           /* 主色（按钮、复选框、强调） */
--pos-primary-dark: #ffffff;      /* 主色 hover */
--pos-text: #e8e6e1;              /* 正文文字 */
--pos-text-secondary: #9a9c9e;    /* 次要文字 */
--pos-muted: #5f6165;             /* 弱化文字 */
--pos-border: rgba(255,255,255,.08);        /* 细描边 */
--pos-border-strong: rgba(255,255,255,.22); /* 强描边 */
--pos-accent-soft: #2a2e34;       /* 强调底 */
--pos-tick: #141414;              /* 复选框对勾颜色 */
--pos-on-primary: #141414;        /* 主色块上的文字 */
--pos-radius: 11px;               /* 卡片圆角 */
--pos-shadow: 0 6px 18px rgba(0,0,0,.4);    /* 卡片阴影 */
```

例如想换成微暖的深灰底：把两处 `--pos-bg` 改成 `#121110`，`--pos-surface` 改成 `#1a1817`，保存后回到工作台即可看到效果（CSS snippet 热生效，无需重启）。

## 二、换背景图

当前背景图是 `工作台工作台内部/Assets/Hero/hero.jpg`，**直接用同名新图覆盖它**即可，文件名、路径都不用改（改了名字就要同步改 `view.js` 顶部的 `HERO_PATH` 常量）。

选图建议：

- **比例**：16:9 或 16:10 横版，≥1920×1080（建议 2560×1440）；
- **内容**：偏暗、低细节、画面主体靠下、边缘无重要信息的图效果最佳——页面按 `center bottom/cover` 锚定**底部**（地平线贴住页面下缘），上半部分会被暗化遮罩压暗以保证文字可读。

遮罩强度与玻璃模糊度可微调，都在 `工作台工作台内部/Views/Dashboard/view.css`：

- `.pos-bg-overlay` 的渐变 `rgba(14,15,17,.88) → .72`（背景暗化遮罩）；
- `[data-bgmode="glass"]` 下的 `backdrop-filter: blur(16px) saturate(1.15)`（玻璃卡模糊半径）。

## 三、直接改数据（手编任务文件）

六个分区文件就是全部数据，用任何编辑器手编都行，**下次打开工作台即生效**。规则只有四条：

```markdown
- [ ] 这是一个任务
- [x] 这是已完成任务 ✅ 2026-09-01
    - [ ] 这是子任务（缩进 4 个空格，只许一级嵌套）
    - [x] 已完成子任务 ✅ 2026-09-01
```

1. **只认复选框行**：`- [ ]` / `- [x]` 开头的行才算任务；空行、标题、普通文字一律忽略，写错也不会弄坏数据。
2. **完成标注**：`- [x]` 行尾的 ` ✅ YYYY-MM-DD` 是完成日期，只在勾选状态下存在；没写日期的 `[x]` 行也能容忍（视为无完成日期）。
3. **子任务**：紧跟在父任务下一行，**缩进固定 4 个空格**（不要用 Tab），只许一级，不再嵌套。
4. **整文件重写**：系统每次保存会把整个文件重写成规范形态（多余文字被忽略、格式被规整），手编内容以「被解析后的复选框行」为准。

> [!note] 手编与界面互不冲突
> 文件里没有 ID，任务的身份就是「所在分区 + 那行文字」。重复文字行互不干扰，各自是独立任务。

## 四、改行为 / 布局（改代码）

| 想改什么 | 改哪里 |
| --- | --- |
| 页面结构、交互行为、拖拽规则、清扫逻辑 | `工作台工作台内部/Views/Dashboard/view.js`（行为）+ `view.css`（样式） |
| 数据解析 / 写盘规则、分区定义 | `工作台工作台内部/Services/task-service.js`（数据层） |
| Obsidian 页面壳样式 | `工作台工作台内部/Styles/dashboard.css` |

- 工作台的交互与视觉**一手资料是原型**：`prototype/工作台UI原型.html`（在 `MyTask-OS` 的上一层目录，不在仓库内）。浏览器直接打开即可对照，`view.js` / `view.css` 是它的 Obsidian 移植版，函数与类名一一对应（如 `renderD` → `layoutHTML`、`dragVal/dropSpec` 同名）。
- `task-service.js` 整体是一个 JS 表达式工厂，被 `view.js` 用 `new Function("return " + src)` 加载——**别把它改成模块**（不能出现 `require` / `import`），也别在 `return` 与表达式之间插入含换行的块注释。
- 改动后重启 Obsidian（或重载仓库）让 Dataview 重新执行视图。

## 五、改完怎么自测

本项目的自动化测试放在 Vault 外的 `.scratch/` 目录（`MyTask-OS` 仓库根在 `MyTask-OS/` 自己身上，`.scratch` 与 `prototype` 都在仓库外，不会被 git 提交带走，也不会被 Obsidian 索引）。在 `MyTask-OS` 的**上一层目录**执行：

```bash
node .scratch/mytask-os/tests/test-task-service.js     # 数据层回环测试（7 项）
node .scratch/mytask-os/tests/test-view-dashboard.js   # 视图全场景冒烟测试（199 项）
node --check "MyTask-OS/工作台工作台内部/Services/task-service.js"
node --check "MyTask-OS/工作台工作台内部/Views/Dashboard/view.js"
```

两条测试全绿即数据层与视图行为未破坏。最后回到 Obsidian 里人工过一遍：勾选、拖拽（排序 / 嵌套 / 跨区 / 复活）、隔夜归档（把某行 ✅ 日期改成昨天、切回工作台看是否扫入）、手编文件生效。
